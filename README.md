### 📌 Challenge Information

- 📅 **Day:** 95

- 💻 **Platform:** SQL Challenge

- 📸 **Submission Screenshot:** Screenshot 2026-10-29 135008.png
- 📁 **Directory:** Day95-SQL
- ✅ **Status:** Completed

### 🎯 Challenge Objective

Understand typical SQL subquery use cases and learn how nested queries help retrieve and filter data based on the results of another query.

### 📚 What Is a Subquery?

A subquery is a SQL query nested inside another SQL statement. The inner query supplies a result that the outer query can use to filter records, compare values, retrieve information, or perform calculations.

Subqueries are commonly used in the WHERE clause and can also appear in the FROM and SELECT clauses, depending on the query structure and SQL dialect.

### 💡 What I Learned

- 🔹 Understanding inner queries and outer queries.
- 🔹 Using subqueries in the WHERE clause for conditional filtering.
- 🔹 Using comparison operators with subqueries.
- 🔹 Applying aggregate functions inside subqueries.
- 🔹 Exploring subqueries in FROM as derived tables.
- 🔹 Using scalar subqueries in SELECT.
- 🔹 Retrieving data dynamically without hardcoding calculated values.
- 🔹 Understanding how nested queries simplify multi-step data retrieval.

### 💻 Example SQL Query

    SELECT name, salary
    FROM employees
    WHERE salary > (
        SELECT AVG(salary)
        FROM employees
    );

### 🔍 Query Explanation

1. The inner query calculates the average salary of all employees.
2. The outer query retrieves employee names and salaries.
3. The WHERE clause compares each employee's salary with the calculated average.
4. Only employees earning more than the average salary are returned.

### 💡 Explanation

## 🆕 Day 93 – Subqueries in SQL (MCQ)

### 📌 Challenge Information

### 🎯 Challenge Objective

Understand the purpose and usage of subqueries in SQL and identify the correct statement about where subqueries can be used.

### ❓ Question

Which of the following statements about subqueries is true?

**Options:**

1. Subqueries can only be used in SELECT statements.
2. Subqueries always return a single row of data.
3. Subqueries must be enclosed in square brackets.
4. Subqueries can be used in various parts of a SQL statement.

### ✅ Correct Answer

**Option 4: Subqueries can be used in various parts of a SQL statement.**

### 💡 Explanation

A subquery is a query nested inside another SQL query. Depending on the query and SQL dialect, subqueries can be used in different clauses, including SELECT, FROM, WHERE, and HAVING.

They help retrieve data, filter records, compare values, and perform calculations using the results of another query.

### 💻 Example SQL Query

    SELECT title, rating
    FROM Properties
    WHERE rating > (
        SELECT AVG(rating)
        FROM Properties
    );

### 🔍 Query Explanation

1. The inner query calculates the average rating of all properties.
2. The outer query retrieves property titles and ratings.
3. The WHERE clause selects properties whose ratings are greater than the calculated average.

### ❌ Why the Other Options Are Incorrect

- **Option 1:** Subqueries are not restricted to SELECT statements. They can appear in several supported SQL clauses.
- **Option 2:** Subqueries can return a single value, one row, multiple rows, or multiple columns, depending on their structure.
- **Option 3:** SQL subqueries are generally enclosed in parentheses `()`, not square brackets `[]`.

## 🆕 Day 92 – Rearrange the Query - 2

### 📌 Challenge Information

- 📅 **Day:** 92
- 🧩 **Challenge:** Rearrange the Query - 2
- 💻 **Platform:** SQL Challenge
- 🗄️ **Language:** SQL
- 🔗 **Topic:** SQL JOINs
- 📋 **Concepts:** CROSS JOIN, SELECT *, LIMIT
- 📸 **Submission Screenshot:** Screenshot 2026-10-26 094947.png
- 📁 **Directory:** Day92-SQL
- ✅ **Status:** Completed

### 🎯 Challenge Objective

Combine the `user_information` and `complaint_status` tables using a CROSS JOIN and retrieve the first five rows.

### 💻 Correct SQL Query

    SELECT *
    FROM user_information ui
    CROSS JOIN complaint_status cs
    LIMIT 5;

### 🔍 Query Explanation

**1. SELECT \***

Retrieves all columns from both tables.

**2. FROM Clause**

Selects `user_information` as the first table. The alias `ui` is used as shorthand.

**3. CROSS JOIN**

Combines every row from `user_information` with every row from `complaint_status`.

**4. LIMIT 5**

Restricts the displayed output to five rows. Without an ORDER BY clause, the particular five rows returned are not guaranteed.

### 🧠 SQL Concepts Practiced

- SELECT Statement

- Cartesian Product
- Table Aliases
- Multi-Table Queries
- LIMIT Clause
- Query Rearrangement
- Result Set Interpretation

### 🎓 Learning Outcome

This challenge strengthened my understanding of how CROSS JOIN produces every possible combination of rows from two tables.

**Key Takeaway:** If one table contains *m* rows and another contains *n* rows, a CROSS JOIN produces *m × n* combinations before any filtering or limiting.

## 🆕 Day 91 – Rearrange the Query - 1

### 📌 Challenge Information

- 📅 **Day:** 91
- 🧩 **Challenge:** Rearrange the Query - 1
- 💻 **Platform:** SQL Challenge
- 🗄️ **Language:** SQL
- 🔗 **Topic:** SQL JOINs
- 📋 **Concepts:** INNER JOIN, ON, WHERE, Table Relationships
- 📸 **Submission Screenshot:** Screenshot 2026-10-25 070800.png
- 📁 **Directory:** Day91-SQL
- ✅ **Status:** Completed

### 🎯 Challenge Objective

Rearrange the SQL code fragments into the correct order to retrieve the category ID, category name, subcategory ID, and complaint reason for category ID `1`.

### 💻 Correct SQL Query

    SELECT
        cc.category_id,
        cc.category_name,
        cd.subcategory_id,
        cd.reason
    FROM category_description cd
    INNER JOIN complaint_category cc
        ON cc.category_id = cd.category_id
    WHERE cc.category_id = 1;

### 🔍 Query Explanation

- **SELECT:** Specifies the columns to retrieve.
- **FROM:** Identifies the starting table.
- **INNER JOIN:** Combines records from related tables.
- **ON:** Specifies the matching category ID in both tables.
- **WHERE:** Filters the results to category ID `1`.

## 📖 Learning Approach

My daily learning process includes:

1. 📖 Understand the SQL problem statement.
2. 🧠 Analyze the expected output.
3. 🔍 Identify the required tables and columns.
4. 🔗 Understand relationships between tables.
5. 🔄 Identify matching and related records.
6. ✍️ Write the SQL query or select the correct answer.
7. 🧪 Test the query when applicable.
8. 🔍 Understand the result.
9. 🛠️ Debug errors when required.
10. 📊 Analyze the query logic.
11. 📂 Save the solution in this repository.
12. 📸 Add the successful submission screenshot.
13. 📝 Review the SQL concepts used.
14. 🚀 Continue to the next challenge.
